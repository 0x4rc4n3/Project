Cryptographic Inventory & Security Objectives

Detailed breakdown of cryptographic mechanisms, locations, and security rationale

Mechanism Location Objective & Rationale
ML-DSA-65
Post-Quantum Signature		 crypto-service/pq_sign.py
fragmentation-module/src/pq_sign.py 		Authenticity & Non-Repudiation (Quantum-Resistant):
FIPS 204 approved signature algorithm that ensures credential integrity and issuer authenticity remain secure even against future quantum computers running Shor's algorithm.
Shamir's Secret Sharing (3-of-5)
Symmetric Sharding		 crypto-service/shamir.py
verification-api/src/routes/issue.js 		Zero Single Point of Compromise:
Splits the signed credential payload into 5 shares. A verifier needs 3 shares to reconstruct it, ensuring no single database contains a complete stealable copy of any credential.
HashiCorp Vault KV
Secrets Manager		 crypto-service/kms.py Centralized Private Key Protection:
Stores the issuer's ML-DSA-65 private signing key directly in Vault's encrypted storage. The key is retrieved directly over authenticated API calls at startup and held strictly in-memory. No keys are ever written to disk or environment variables.
SHA3-256
Quantum-Resistant Hash		 crypto-service/interface.py
verification-api/src/routes/verify.js 		Data Integrity & Verification:
Provides one-way hashing of claims and shares. The blockchain stores the anchor hash to detect tamper attempts, and database shares are matched against their pre-computed hashes.
TLS / HTTPS
Secure Transport		 crypto-service/app.py (Port 5001)
verification-api/src/chain/fabric.js 		Confidentiality in Transit:
Encrypts the microservice communications. Node-to-Python requests run over HTTPS, and Peer-to-Orderer/Client gRPC calls leverage mTLS certificates.
Bearer API Key
Access Control		 crypto-service/app.py
verification-api/src/routes/issue.js 		Authorization & Isolation:
Protects the internal cryptographic microservice endpoints from unauthorized local or external invocation.

Architectural Boundaries

Boundary 1: Node API ↔ Python Crypto

HTTPS over localhost:5001. Authenticated via API key, shards hex-encoded for JSON serialization.

Boundary 2: Node API ↔ Fabric Gateway

gRPC connections with TLS certificates. Identity authentication via IssuerMSP.

Boundary 3: Peer ↔ Orderer ↔ Peer

Raft Consensus inside Docker bridge network (`scatterid_net`) using mutual TLS.
